## 1. The product (one paragraph)
ScriptBreak is an on-device safety layer inside a UPI payment app. Just before the UPI PIN, it checks
whether the payment looks like a **coached scam** (a scammer guiding the victim live on a call or
screen-share, a payee never paid before, an amount out of character). It shows one of four levels
(None / Nudge / Pause / Critical), says **why**, and offers **"Ask family"**, which alerts a trusted
relative's phone. It never blocks: the person always decides. Tagline: "Break the scam script before the PIN."
Round 1 one-liner (use exactly): *"ScriptBreak is an on-device layer for UPI apps that spots payments
matching a coached-scam pattern, shows the plain facts before the PIN, and brings in family with one tap."*

Example: Mr. Sharma, 64, on a "CBI digital arrest" video call, pays ₹48,000 (74× his usual ₹650) to a new
payee "Ramesh K." → Pause → he answers Yes to Q1 → Critical → taps "Ask Rohit (son) to call me" →
Rohit's phone buzzes → Rohit calls → scam breaks.

## 2. Decisions made on 24 Oct (current direction, overrides Round 1 where different)

   (the form promised "Rules stay as safety guardrails").
3. **One app, 5 modes** chosen at start: User Mr. Sharma, User Priya, Family Rohit (second phone),
   Judge mode, Analyst.
4. **No real login**: a profile picker. Trusted-contact setup with a demo OTP; changing it later shows
   "Active in 24 hours".
5. Fake UPI app has **its own name and branding ("DemoPay")**, never PhonePe/GPay look or logos.
   Show "Demo app – no real money". All names, UPI IDs, numbers fictional.
6. Signals detected **automatically** on the phone (call state, pasted UPI ID, app switch, night, payment
   history). Judge mode can override any input (judges must be able to vary inputs).
7. Family alert via **Firebase** (free) between two phones.

## 5. The AI model (`ml/`, built and tested 24 Oct)
**Run order:** `pip install -r requirements.txt`, then `python make_dataset.py` (5 s) → `train.py` (1 min) →
`export_model.py` → `evaluate.py` (3 min) → `analyst_discovery.py --unseen sent_by_mistake` (40 s).
Fully reproducible (same seeds → identical model).

**Data (synthetic only, sizes match the form):** generated by Round 1 `round1/generator.py`.
train 1,40,000 genuine + 10,000 genuine lookalikes + 2,100 × 8 scam types; val 30,000 + 450 × 8;
test 30,000 + 450 × 8 with **shifted settings and new seeds**. Labels from the generated scenario
(1 scam / 0 genuine), **never from rules**. Scam types: digital_arrest, customer_care, kyc_official,
courier, voice_clone, hang_up_and_pay, sent_by_mistake, chat_task. The 28 stories are never training data.

**Record format** (`ml/schema.json`): `{scenario_id, workflow, features{...}, label}`. Features (16):
amount, median_90d, payments_90d, call_now, call_seen_30m, screen_share, payee_status
(known|new|recent|warned|flagged), payee_kind (person|merchant|biller), same_payee_24h, new_payees_60m,
sent_new_24h, credit_unknown_48h, payee_is_sender, payee_pasted, app_switch, night.
`features.py` turns them into 24 numbers (the ONLY definition; Kotlin mirrors it).
Model never sees scenario_id, workflow, label, or the Q1/Q2 answers.

**Models:** logistic regression, random forest, gradient boosting; thresholds set on validation so
~6.5 genuine per 1,000 are interrupted (budget ≤ 8). Selected: **gradient boosting** (200 trees, depth 3);
val scams flagged 86.3% vs LR 83.5%, RF 83.3%. Thresholds: nudge 0.071, pause 0.486, critical 0.942.

**Test results (synthetic, unseen):**
| | AI model | Round 1 rules v0.3 | Bank rule (new person ≥ ₹10,000) |
|---|---|---|---|
| Scams flagged, 6 in-scope types | **80%** | 60% | 24% |
| Genuine interrupted per 1,000 | **7.3** | 7.7 | 3.6 |
Per type: digital arrest 89%, courier 82%, voice clone 81%, hang-up-then-pay 79%, customer care 74%,
KYC 73%, chat task 64%, sent-by-mistake 100%. ROC AUC 0.994. Nudge on 20/1,000 genuine.
Hidden-type test (retrain without that type): call-based types still 67–83%, hang-up 70%,
**sent-by-mistake only 11%**, chat task 38%. 28 stories: 14/16 scams flagged, 2/10 genuine interrupted.
**Known failures (say them openly):** S06 splitting small payments to several new accounts on a call
(score 0.06, missed); S08 first small payment only Nudge; L04 ₹40,000 new-landlord deposit wrongly Paused;
most false alarms = genuine first payment to a new person during a call.
Always say: synthetic results test our assumptions, not real-world accuracy.

**On the phone:** `scam_model.json` (91 KB) + `ml/android/ScamModel.kt` (no network, no ML library,
~0.1 ms/payment). Kotlin output matches Python exactly on 500 vectors (`test_vectors.json`,
`ScamModelParityTest.kt`). API: `ScamModel.fromAssets(context).assess(Payment(...), q1, q2, approvedRules)`
→ `Result(level, score, reasons[≤3], guardrails, modelVersion)`. Reasons are grouped plain sentences,
e.g. "The amount is 74 times your usual payment · You have never paid this payee before · You are on a call right now".

**Safety layer (`policy.py` = Kotlin `assess`):** score → level; G1 flagged payee → Critical;
G2 warned payee → ≥ Nudge (Critical with live call/screen-share); G3 analyst-approved rule → ≥ Pause;
G4 "Yes" to Q1/Q2 at Pause+ → Critical. Answers only RAISE the level. App: "Continue anyway" always
available; if scoring throws, the payment goes through (fail-open).

**Analyst console (AI discovery, promised on the form):** reports the model missed are clustered
(average-linkage hierarchical clustering, Jaccard distance, silhouette-chosen cut); a rule is proposed per
cluster (≤ +0.5 false alarms/1,000, ≥ 70% of cluster). Demo file `discovery_unseen_sent_by_mistake.json`:
model never trained on "sent by mistake" → AI finds a pure 89-report cluster → rule "same amount as money
received from a stranger + new payee, not paying back that sender" catches 100% for +0.05/1,000 →
analyst taps Approve → phone now pauses it (G3). With the full model (`discovery.json`) no rule is cheap
enough, so all are rejected; that is honest too.
